# ADR-001 — WordPress Theme Approach

**Status:** Approved  
**Date:** 2026-11-06  
**Related Requirements:** REQ-005, REQ-006, REQ-013, REQ-038, NFR-001, NFR-004, NFR-013  
**Related Specifications:** SPEC-005, SPEC-006, SPEC-013, SPEC-025, SPEC-028, SPEC-037, SPEC-038

---

## Context

The portfolio requires a modern WordPress implementation that supports:

- Professional portfolio content
- Maintainable skills and project content
- Resume management
- Accessibility
- Performance
- Minimal dependencies
- Content editing without code where required
- Future maintainability

The project should avoid unnecessary page-builder dependencies and should provide a practical opportunity to learn modern WordPress architecture while applying Spec-Driven Development.

---

## Options Considered

### Option A — Custom Classic Theme

Build the site using the traditional WordPress theme architecture with PHP templates.

**Advantages:**
- Familiar PHP/template model
- Mature and well understood
- Full control over templates

**Disadvantages:**
- Less aligned with modern WordPress block-based editing
- Greater reliance on custom template implementation
- Less opportunity to use native Gutenberg capabilities

---

### Option B — Custom Block Theme

Build a custom WordPress Block Theme using modern WordPress site-editing and Gutenberg capabilities.

**Advantages:**
- Modern WordPress architecture
- Native Gutenberg integration
- Supports structured content editing
- Reduces dependence on page builders
- Provides a strong foundation for accessible and maintainable templates
- Aligns with the project's learning objective

**Disadvantages:**
- Requires learning block-theme concepts
- Requires careful template and styling design
- Content architecture still needs to be deliberately designed

---

### Option C — Minimal Starter / Hybrid Theme

Use an existing lightweight starter theme and customize it.

**Advantages:**
- Faster initial development
- Can provide established foundations

**Disadvantages:**
- Introduces external architectural assumptions
- May include unnecessary functionality
- Can make the source architecture less clear for the SDD learning objective

---

## Decision

Use a **Custom WordPress Block Theme** for V1.

The theme will use native WordPress/Gutenberg capabilities wherever practical.

Page builders such as Elementor or WPBakery are not part of the approved architecture.

---

## Reason

The Custom Block Theme provides the best balance between:

- Modern WordPress practices
- Content maintainability
- Accessibility
- Performance
- Minimal dependencies
- Long-term maintainability
- SDD learning value

It also supports the project's goal of building a real portfolio while learning how architectural decisions can be derived from requirements and specifications.

---

## Consequences

### Positive

- Modern WordPress foundation
- Native Gutenberg editing
- Reduced page-builder dependency
- Better alignment with content maintainability requirements
- Greater control over performance and accessibility
- Clear ownership of the theme architecture

### Negative

- Additional learning required around block themes
- More responsibility for template and styling architecture
- The theme must be deliberately designed rather than relying on an existing page builder

---

## Constraints

The block theme must remain simple and appropriate for a personal portfolio.

The project must not introduce abstractions or framework-like architecture without a demonstrated requirement.
