
# Project: Personal Professional Portfolio

## Project Methodology

This project follows Spec-Driven Development (SDD).

The specification is the source of truth.

The project follows this lifecycle:

Idea → Requirements → Specification → Architecture → Technical Design → Implementation Plan → Implementation → Testing → Review → Deployment

## Core SDD Rules

- Do not implement functionality that is not covered by an approved specification.
- Do not assume missing requirements.
- If a requested change is ambiguous, ask for clarification.
- Before implementing a feature, identify its relevant requirement, specification, design, and implementation task.
- If implementation differs from an approved specification, explicitly identify the specification drift.
- Never silently change the intended behavior defined by the specification.
- When a requirement changes, identify affected downstream artifacts.

## Working Principles

- Prefer simple solutions over unnecessary complexity.
- Avoid premature architecture and abstraction.
- Do not introduce technologies or dependencies without a documented reason.
- Follow WordPress best practices when implementation begins.
- Accessibility, security, SEO, performance, and maintainability are first-class concerns.
- AI-generated code must be reviewed against the approved specifications.

## Change Discipline

Before making a significant project change:

1. Determine whether the change affects the vision.
2. Determine whether requirements are affected.
3. Determine whether specifications are affected.
4. Determine whether architecture or technical design is affected.
5. Determine whether implementation tasks or tests are affected.
6. Identify any required documentation updates.
